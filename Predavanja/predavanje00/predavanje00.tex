\begin{frame}{Ishodi učenja}
Nakon položenog kolegija student može:

\begin{itemize}
  \item modelirati domenu i preslikati je u relacijsku bazu zajedno s ograničenjima
  \item oblikovati programsko sučelje API (engl. \emph{application programming interface}) u stilu REST (engl. \emph{representational state transfer}) i validirati ulazne podatke
  \item implementirati autentikaciju tokenom JWT (engl. \emph{JSON Web Token}) te autorizaciju po ulozi i po vlasništvu zapisa
  \item izraditi jednostraničnu aplikaciju (engl. \emph{single-page application}, SPA) koja se oslanja na taj API
  \item napisati testove poslovnih pravila i postaviti aplikaciju u produkcijsku okolinu
\end{itemize}
\end{frame}

% ------------------------------
\begin{frame}{Pretpostavljeno znanje}
\begin{itemize}
  \item programiranje u jeziku opće namjene; sintaksa Pythona uvodi se usput
  \item osnove relacijskih baza: tablica, primarni i strani ključ, upit \texttt{SELECT}
  \item osnove HTML-a i CSS-a
  \item rad s Gitom: \texttt{commit}, \texttt{branch}, \texttt{remote}
\end{itemize}

\vspace{0.4em}

\end{frame}

\begin{frame}{Radni primjer: aplikacija za prijavu na natjecanje}
Kroz ovaj ćemo kolegij graditi sustav prijava klubova na powerlifting natjecanje.

\begin{itemize}
  \item Klub prijavljuje svoje natjecatelje i vidi samo svoje prijave; organizator vidi prijave svih klubova.
  \item Natjecanje ima dva roka nominacije. Do prvoga roka prijave se dodaju, mijenjaju i povlače. Između rokova mogu se još mijenjati i povlačiti, ali ne i dodavati. Nakon drugoga roka popis je zaključan.
\end{itemize}

\vspace{0.4em}
Ista se struktura pojavljuje u mnogim sustavima: korisnik vidi dio podataka, a operacije nad njima ovise o tome u kojem je stanju nadređeni zapis.
\end{frame}

% ------------------------------------------------------------

\begin{frame}{Studentski projekt}
Tijekom semestra svaki student izrađuje vlastitu aplikaciju, po uzoru na referentnu, ali u drugoj domeni. Zahtjevi:

\begin{itemize}
  \item autentikacija tokenom i najmanje dvije uloge s različitim pravima
  \item najmanje dva entiteta povezana relacijom
  \item vlasništvo nad zapisom: korisnik vidi i mijenja samo svoje podatke
  \item najmanje jedno pravilo ovisno o stanju ili vremenu: status, faza ili rok
  \item sučelje sa stanjima učitavanja, pogreške i praznog skupa rezultata
\end{itemize}

\vspace{0.4em}
Predaja je u dva dijela, svaki nosi 40 bodova: prvi obuhvaća backend, drugi cjelovitu aplikaciju postavljenu u rad.
\end{frame}

% ------------------------------
\begin{frame}{Tema projekta}
Neke od mogućih tema projekta su:

\begin{itemize}
  \item rezervacija termina: dvorane, treneri, konzultacije
  \item prijave na događanja: kapacitet, lista čekanja, evidencija dolaska
  \item praćenje zadataka: projekti, statusi, komentari
  \item planovi treninga: programi, izvedbe, napredak
  \item odobravanje dokumenata: zahtjev, razine odobrenja, verzije
  \item mali oglasnik: oglasi, poruke, spremljeni oglasi
  \item evidencija članstva: članovi, uplate, statusi
\end{itemize}

\vspace{0.6em}
Potpuni popis zahtjeva naveden je na stranici predmeta.
\end{frame}

\begin{frame}{Akademska čestitost i uporaba AI alata}
Uporaba AI alata i vanjskih izvora dopuštena je. Uvjet je da student razumije i objasni svaki dio predanoga koda; na obrani se provjerava razumijevanje.

\vspace{0.4em}
Za svaki preuzeti isječak koda treba znati:
\begin{itemize}
  \item koji problem rješava i uz koje pretpostavke
  \item kako se ponaša u rubnim slučajevima: prazan ulaz, istekao \emph{token}, istodobni zahtjevi
  \item koji ga test pokriva
\end{itemize}
